# 业务页面组合范式

本文面向从 Starter 创建的业务 app，指导把现有能力组合成一致的页面。以下结构树是职责示意，不是已实现的组件名或可直接复制的 Vue API。Starter 保持轻量，不预装业务页面、演示数据或 Mock Server。

## 使用顺序与权威来源

1. 阅读目标页、父布局和同级页面，优先沿用当前产品已有的结构与交互。
2. 选择下方范式；一页可以组合多个范式，局部调整只检查受影响部分。
3. 按 [公共能力发现](./shared-capability-usage.md) 确认候选组件及其当前版本 API；不要根据本文的结构名称猜测组件存在。
4. 在编码前确认页面位置、主操作、提交单元、内容状态、滚动区域和组件复用边界。简单页面只需简短说明，不要求另建计划文档。
5. 按末尾场景核验，并在交付中区分自动检查与人工界面验收。

## 共同结构

- 一页有明确标题和主要内容区域。父布局已经提供 `main` 时，子页面使用 `section` 等语义容器，避免嵌套 `main`；标题层级跟随父布局。
- 页面级主操作靠近标题，分区操作靠近分区标题，行操作留在行内；不要在多个位置重复放置同一个主要操作。
- 标题、导航、筛选和内容区的顺序在同级页面保持一致。组件及插槽的主视图区、伸展方向和滚动边界按 [主视图区与空间分配](../rules/84-ui-implementation.md#主视图区与空间分配) 判断，沿用父布局契约。
- 宽度、留白、文字层级与主题遵守 UI implementation；不为套范式额外增加空卡片或固定高度。
- 页面框架先复用当前 app。确有多个页面重复时，再封装 app 内的页头、分区、设置项或列表容器；先明确 props、slots、events，不为每页创建一套相似组件。
- 操作权限由业务层解释；无编辑权限但允许查看时提供只读展示。是否隐藏不可用操作或保留 disabled 状态，由用户是否需要理解原因决定。

## 列表页

适合需要搜索、筛选、排序、分页或进入详情的资源集合。

```txt
路由页：标题、创建入口与 URL 状态桥接
  列表 feature
    搜索 / 筛选 / 排序
    内容区域：加载、失败、空结果或列表
      行 / 卡片：身份信息、状态、主要进入入口、局部操作
    分页与总量（接口支持时）
```

- 搜索与筛选靠近结果，批量操作只在有选择项时提供，并清楚说明影响的对象范围。
- 无任何资源的空状态解释资源用途，并在有权限时提供创建入口；筛选无结果提供修改或清除筛选入口。二者不是同一文案和操作。
- 筛选或排序变化后按分页契约回到有效页；删除最后一项导致页码越界时，进入有效页并重新获取，不能停留在虚假的“没有资源”。
- 行整体可进入详情时，菜单、复选框和按钮保持独立可操作；不嵌套交互元素，不让行点击吞掉内部操作。
- 表格或卡片的选择取决于字段比较、信息密度和用户任务。窄屏优先保留身份、关键状态和操作，必要时允许表格区域横向滚动，不裁掉关键动作。

组合示例：资源列表的创建入口放在页头；搜索条件通过路由 query 桥接给列表 feature；feature 使用当前请求封装读取结果，用已核实的 data-table 或 UI table 组合展示。创建成功后按当前请求能力刷新关联列表；刷新策略仍由请求规则决定。

## 详情页

适合有独立身份、需要直达或刷新恢复的对象。

```txt
路由页：对象 ID、返回位置、访问边界
  标题区：对象名称、状态、页面级操作
  详情分区：摘要、属性、关联信息
  子路由 / 局部 tab（按 URL 语义选择）
```

- 从列表进入详情后，返回时保留适合进入 URL 的列表条件。直达详情时也提供有效的父级入口，不只依赖浏览器历史回退。
- 对象不存在、无访问权限和读取失败分别表达。只有实际契约能区分时才区分，不从错误文字猜测状态，也不暴露无权限对象的信息。
- 操作改变对象状态后同步相关摘要与操作可用性；操作仅影响某个分区时，不替换整张详情页。
- 重要业务 tab 需要直达、刷新或浏览器历史时使用路由；普通局部切换继续遵循 routing rule。

组合示例：设备详情由路由 ID 确定对象，页头展示设备名和状态，信息区与活动区分别组织；编辑只影响属性时，在该区域进入编辑范式，保留其他可读内容。

## 设置页

适合按主题组织少量配置、独立编辑项或多个提交单元。

```txt
页面标题与说明
  设置分区：标题、用途
    设置项：名称、帮助信息、值 / 控件、状态
  其他设置分区
  高影响操作分区（存在时）
```

- 设置项名称、帮助信息与控件在同级页面采用一致的对齐和宽度策略。窄屏按名称、说明、控件、反馈的阅读顺序纵向排列。
- 先判断独立字段还是统一提交单元，再按 add-form 选择能力。立即生效、逐项保存和整组保存不能只靠按钮位置暗示，应让交互可辨认。
- 无编辑权限时优先保留有意义的当前值，不把整页表现成加载或故障。
- 高影响操作与普通设置分区分开，说明实际后果和影响对象，按业务风险决定确认步骤；取消后焦点回到触发入口。
- 保存失败保留输入，成功后展示服务端确认的值；刷新不得无提示覆盖仍在编辑的草稿。

组合示例：个人设置中的独立昵称编辑和需共同校验的密码修改是不同提交单元；各自的 pending、错误和取消只影响自身，不共享一套整页提交状态。

## 编辑页与编辑流程

适合新建、修改、条件编辑、弹窗表单或有明确步骤的业务流程。是否路由化由 routing rule 决定。

```txt
路由页 / 编辑容器：标题、返回或关闭入口
  表单 feature：初始值、草稿、校验、字段错误
    按任务分组的字段
    表单级反馈（需要时）
    取消 / 重置 / 提交
```

- 编辑前先确认 initial values、已提交值、草稿与提交后的去向；取消、重置和清空的语义按 add-form，不混用。
- 提交失败保留草稿与可修正信息；成功后再按流程返回、进入详情或继续编辑。不要只弹成功提示而让页面停在含糊的旧状态。
- 有未保存修改时，明确路由离开、关闭容器和切换对象是否需要确认或保留草稿；没有修改时不机械弹确认。
- 后台刷新不能悄悄覆盖草稿。服务端对象已变化且会影响提交时，按实际契约提示重新载入或处理冲突，不自行构造版本协议。
- 分步流程标明当前步骤与返回路径，回到前一步时保留已输入值；只有业务要求或依赖关系成立时，才阻止跳步。
- 同一表单只保留一个清晰提交入口。提交 pending 时防止重复提交；取消能否中止已开始的写入，以接口能力为准，不能关闭窗口后声称请求已取消。

组合示例：新建资源页使用一个表单 feature 管理同一对象的字段与提交；成功后进入返回对象的详情位置，失败仍停留在编辑态并保留输入。字段 API 和表单绑定方式先查当前版本资料。

## 状态组合与恢复

下面描述用户看到的页面状态，不要求新增一套状态管理。直接消费当前请求与表单契约，状态解释遵循 request feedback 和 error handling。

| 条件                      | 内容与操作                                                                 |
| ------------------------- | -------------------------------------------------------------------------- |
| 首次读取，尚无内容        | 受影响区域展示接近最终结构的 skeleton；不提前显示空结果                    |
| 读取成功，有内容          | 展示内容及当前权限允许的操作                                               |
| 读取成功，无资源 / 无匹配 | 按列表范式分别提供创建或调整筛选入口                                       |
| 首次读取失败，内容不可用  | 错误仅替换受影响区域，提供实际可执行的恢复入口                             |
| 已有内容正在刷新          | 按数据有效性保留可用内容，局部反馈刷新；身份或对象变化时不能显示旧对象内容 |
| 刷新失败但原内容仍有效    | 按影响说明数据状态并允许重试；不把原有内容误作最新结果                     |
| 某项提交或操作 pending    | 反馈绑定触发按钮、行或提交单元，不锁住无关内容                             |
| 提交失败                  | 保留草稿或回到已确认状态，提供可修正的信息；不把失败当作空结果             |
| 只读 / 权限变化           | 保留允许查看的信息，调整可用操作；禁止以客户端隐藏替代服务端授权           |

## 页面验收场景

根据本次影响选择相关项，不为不涉及的状态额外创建功能：

- 列表：首次加载、正常结果、真实空集合、筛选无结果、失败重试、删除后有效页、返回后筛选恢复。
- 详情：直接访问、刷新、返回父级、对象不存在、权限不足、局部更新后的状态一致性。
- 设置与编辑：只读、有效提交、无效值、重复提交、失败保留输入、取消、重置、未保存离开及刷新与草稿并存。
- 布局：窄屏下关键操作可达，长名称和错误文案可读，父子滚动区域清楚，只有必要的滚动容器。
- 键盘与辅助技术：输入有名称，图标按钮可识别，焦点可见，弹窗打开和关闭后焦点合理，加载和错误可被感知。
- 主题与动效：明暗主题下对比清楚，状态不只靠颜色，减少动态效果偏好下内容和操作仍完整可用。

自动检查按 quality gates 执行；需要浏览器或真实客户端确认时遵守当前工作区调试授权，交付中列出尚未执行的人工场景。
