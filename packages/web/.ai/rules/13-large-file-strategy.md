# Large File Strategy

## Scope

适用于本仓库新增功能、扩展模块和修改复杂文件的场景。

## 规则

- 不在已经明显过大或同时承担多个职责的文件中继续堆积功能。
- 继续改动会引入新变化原因时，先说明拆分目标、文件边界、实施顺序和风险。
- 代码文件默认遵守 ESLint `max-lines`：去除空行和注释后最多 800 行。
- 超过 800 行但职责单一，且拆分会削弱类型契约、阅读连续性或维护安全性时，可以在文件顶部使用 `/* eslint-disable max-lines -- <中文理由> */`。
- 放行理由必须说明为什么应保持单文件，不能只写“文件太大”。
- 纯局部 bug 修复不强制拆分，但不得显著扩大文件复杂度。
- 拆出的工具、类型、子组件和状态应放在语义正确的 feature、component 或接入边界。
