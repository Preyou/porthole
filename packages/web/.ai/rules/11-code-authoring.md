# Code Authoring

## Scope

适用于本仓库内所有代码和配置改动。

## 改动策略

- 新增、修改、修复功能前，先判断 app 层归属和影响面。
- 优先参考临近页面、feature 和接入层实现，保持结构、命名和交互一致。
- 小问题小改；系统性问题从根源解决。影响面广或会改变公开契约时，先确认方案。
- 不做与当前任务无关的顺手重构、改名或移动。

## 类型与契约

- 信任 TypeScript、OpenAPI、schema 和已经建立的契约。
- 必要校验放在数据进入 app、模块或函数的边界，不在内部多层重复兜底。
- 契约不完整或已知不可靠时，在 API 或配置接入边界集中适配。
- 类型收敛优先考虑 `satisfies`；表达明确类型事实时可使用合适的断言。

## 代码表达与样式

- 逻辑保持清晰、直接，不为不存在的边界写大量防御性代码。
- 只使用一次的简单变量或函数优先内联；抽象应降低真实复杂度。
- 开发要求和实现约束不直接写成界面文案，而是落实为类型、控件、校验、状态或数据处理。
- Tailwind 任意值只在标准工具类无法等价表达时使用。
- 尺寸来源、内部伸缩区及自然最小空间遵守 [尺寸控制](./84-ui-implementation.md#尺寸控制)；主视图区识别、空间分配、自然尺寸及最小高度约束遵守 [主视图区与空间分配](./84-ui-implementation.md#主视图区与空间分配)。

## DOM 获取与操作

- 界面内容、样式和结构通过 Vue 模板、响应式状态及声明式绑定驱动，禁止绕过 Vue 直接操作 DOM。
- 禁止通过 `document.querySelector`、`document.getElementById` 等原生 DOM API 直接查找节点，或自行创建、插入、删除节点。
- 确需访问 DOM（如聚焦、滚动、测量或观察元素）时，必须借助 Vue 的 `useTemplateRef`、VueUse composable 或已有组件公开 API，间接获取元素引用或封装 DOM 操作；元素访问和副作用清理必须遵循组件生命周期。

## 异步、复用与配置

- 无依赖的异步任务并发执行；存在明确数据依赖时才串行。
- 函数不关心异步结果时，不增加无意义的 `await`。
- 实现常见能力前，先检查 app 已有封装、已安装依赖和成熟第三方方案。
- VueUse 有匹配 composable 时优先复用；确实不匹配时才自实现并说明差异。
- 新增环境变量时同步 example 文件和用途注释；私有值放入 `.local`。

## 日志、注释与验证

- 调试时可以添加临时日志，问题解决后移除没有长期诊断价值的输出。
- 新增或修改的代码注释必须使用中文，重点解释原因、约束或取舍，不复述代码表面行为。
- 普通逻辑可以按需添加注释；复杂、有歧义、存在非显然约束或特殊处理的逻辑必须添加注释。
- 只格式化变更文件，并按风险运行最小必要的 lint、type-check、test 或 build。
- 推送前按本仓库 quality gates 完成全量检查。
