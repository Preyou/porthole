# 新增页面

当需要在 app 中新增页面时使用这个技能。

## 流程

1. 读取 `AGENTS.md`。
2. 读取页面相关规则：`40-routing.md`、`70-i18n-and-copy.md`、`84-ui-implementation.md`、`85-business-quality.md`，再读取 `.ai/public/page-recipes.md` 选择页面范式，并确认其操作位置与状态清单。
3. 如果来自截图、Figma、MasterGo 或设计稿，先按 `84-ui-implementation.md` 做 Scope Check，区分 Full Restore、Local Page Restore 或 Small Patch。
4. 判断这个界面是否值得被 URL 表达，确认是否应该成为路由页。
5. 判断页面是模板通用页面，还是复制后的业务 app 页面。
6. 先阅读临近页面和临近功能，沿用目录组织、命名、交互和视觉风格。
7. 先确认页面在现有路由、feature、组件体系中的归属，再决定页面文件、父布局和组件放置位置。
8. 在 `src/views` 新增真实路由页面文件；不要在该目录放非路由组件、状态、工具或测试文件。
9. 普通页面直接使用文件路由默认配置，不写 `definePage()`；存在明确且必要的自定义路由配置需求时才调用，并只设置必要字段。重定向、路由守卫和自定义 route meta 是常见示例，不是穷举。可翻译标题使用稳定的 `titleKey`，静态标题才使用 `title`，按需补充 `icon`、`order`、`type`。
10. 如果页面涉及登录态，先设计认证区与登录后业务区的父路由，并把共享登录鉴权放在登录后业务区父路由；不要假设模板已经提供认证页面。
11. 如果页面有访问要求，在路由页或父布局路由声明权限 meta、页面级守卫、进入条件或重定向规则。
12. 路由页保留简单页面布局和 URL 状态桥接，不要只引用一个功能界面组件，也不要塞入大量业务逻辑。
13. 按 routing rule 判断 URL 状态和表单 query 字段。
14. 新增可见文案时同步 `src/locales`。
15. 页面只用一次的组件、工具、状态和 provider 放到对应的 `src/features` 业务目录；简单且无需拆文件的内容可以直接留在路由页。
16. 写具体组件前，按当前业务库、`@ngt/ui`、自封装的顺序查找或设计组件。
17. 跨页面复用能力再考虑 app 共享目录、`@ngt/ui`。
18. 完成页面初稿后，做一次轻量重复结构检查：
    - 只检查当前新增路由页、对应 feature/component 中的组件、相邻页面和同批设计稿状态。
    - 最多列出 3 类明显重复结构。
    - 同一结构骨架或交互语义出现 2 次以上时，按复用范围抽到对应页面 feature、feature/app 共享目录或 `src/components`，或在获得授权后考虑 `@ngt/ui`。
    - 页面内保留数据数组和 `v-for`，子组件承载重复结构。
19. 按 `86-documentation-sync.md` 判断是否需要同步文档。
20. 按 `90-quality-gates.md` 运行最小必要验证。

## 规则

- 不手改自动生成路由类型。
- `src/views` 只能放真实路由页面；父组件同名目录规则只适用于 `src/features` 和确需多级拆分的 `src/components`。
- 不把具体业务页面写进公共包。
- 影响导航结构时，同步检查菜单和面包屑效果。
- URL 状态、敏感字段和编码策略以 `40-routing.md` 为准。
