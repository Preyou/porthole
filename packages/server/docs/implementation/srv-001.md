# IMP-SRV-001 通用服务端模板实施

## 目标与范围

从 Storyworld 提取认证授权、当前用户、PostgreSQL migration、Redis Session、OpenAPI、统一响应、多语言、日志、来源限制，并交付当前用户私有待办 CRUD。

## 详细设计逐项落实

| 设计条目                   | 具体落位                                                         | 实施章节                 | 验证               |
| -------------------------- | ---------------------------------------------------------------- | ------------------------ | ------------------ |
| 目标、角色、输入输出和状态 | 本文代码结构所列模块                                             | 接口实现契约、控制流程   | 验证方案           |
| 架构、责任与数据流         | 本仓库源码、公开导出及配置                                       | 数据实现、代码边界       | 类型检查与集成验证 |

| 验收条件                   | 文档、类型、Lint、单元与隔离集成测试、OpenAPI 3.1 及健康入口验证 | 验证方案                 | 记录实际结果       |

## 技术约束与非目标

采用 Bun、Elysia、Zod、PostgreSQL/Drizzle、Redis 与 Logto。只使用 PostgreSQL。认证统一支持 Session/Bearer；Authorization 存在时只验证 Bearer，不降级 Cookie。公开路由显式声明，其他业务默认认证。待办归属 ownerId 来自当前身份；已有资源先读取后授权，越权 403，缺失 404。角色、剧本、AI 模型、S3 及其迁移不进入本模板。

## 代码结构与模块落位

src/auth、src/plugins、src/db/pg、src/redis、src/locales、src/constants、src/errors、src/services/auth.ts、users.ts、todos.ts、src/models/todo.ts、src/domain/todos.ts；drizzle；scripts；tests。

## 接口实现契约

GET /api/health 公开返回状态；/api/auth/login、callback/logto、logout 保留原生 OIDC 导航；POST /api/auth/provision 显式 Bearer 建档；GET /api/users/me 返回当前用户。GET /api/todos 按创建时间倒序返回本人待办数组；POST /api/todos 创建；PATCH /api/todos/:id 更新标题或 completed；DELETE /api/todos/:id 删除。标题 trim 后 1..200 字符，PATCH 至少一个字段；completed 为布尔值。列表不增加分页和筛选。响应为 {code,data,message}，HTTP 401/403/404/422/503 保持独立语义。

## 数据实现

### 获取、所有权与分发

| 数据       | 创建/读取位置                                                   | 唯一 owner           | 消费与写入口                                       | 生命周期/失效                                |
| ---------- | --------------------------------------------------------------- | -------------------- | -------------------------------------------------- | -------------------------------------------- |
| 用户与身份 | auth/manager.ts ensureIdentity 与 db/pg/schemas                 | PostgreSQL           | auth 事务写；services/users 只投影认证结果         | 数据库唯一键，用户资料更新后后续认证读取新值 |
| 登录事务   | auth/stateStore.ts createLogin/consumeLogin                     | Redis state 摘要 key | manager 创建；回调原子消费                         | TTL 与一次性消费清理                         |
| Session    | auth/stateStore.ts createSession/getSessionUserId/deleteSession | Redis token 摘要 key | manager 创建、认证读取、退出删除                   | TTL 到期或退出删除，客户端 Cookie 只作凭据   |
| 请求身份   | plugins/sessionAuth.ts resolver                                 | 当前 HTTP 请求上下文 | auth resolver 写；service 只读使用                 | 请求结束释放，不成为跨请求缓存               |
| 待办       | domain/todos.ts，db/pg/schemas/todos.table.ts                   | PostgreSQL todos     | service 经 domain 写入与读取；输出 publicTodo 投影 | 本模块不缓存列表，后续 GET 从数据库读取      |
| OpenAPI    | src/app.ts 的插件与路由 schema                                  | 服务端公开 schema    | 插件生成、export-openapi.ts 读取                   | 契约变化重新导出，不手写客户端生成物         |

### Mutation 一致性

| 操作           | 写入点                                        | 成功后的服务端结果                        | 失败保留                                             |
| -------------- | --------------------------------------------- | ----------------------------------------- | ---------------------------------------------------- |
| 创建待办       | db.insert.returning(publicTodo)               | 返回持久化 DTO，后续本人 GET 可读取       | 校验/授权失败不写入                                  |
| 修改/删除      | transaction 内 SELECT FOR UPDATE 后 authorize | 更新返回触发器处理后的 DTO；删除返回 null | 事务失败回滚，保留原记录                             |
| 回调建档       | ensureIdentity 的 PostgreSQL 事务             | 稳定用户映射；再创建 Session              | 身份写入后 Session 失败不撤销用户资料，不签发 Cookie |
| 显式 provision | 验签后 ensureIdentity                         | 相同 issuer/subject 幂等返回同一用户      | 无效凭据不建档                                       |
| 退出           | manager 删除当前摘要 Session                  | 清 Cookie 并返回身份服务退出地址          | 依赖失败保留原错误，不伪造成功                       |

客户端列表、路由和草稿如何刷新由客户端自己的设计负责，不在服务端复制或管理。

## 组件实现

不适用：本仓库交付 HTTP 服务与 CLI，没有 Vue 组件。Elysia service 通过公开/受保护插件隔离挂载；受保护 resolver 向其后续 handler 提供非空 auth。

## 控制流程

启动入口 `src/index.ts` 使用 `PORT` 监听，并在日志输出 `${env.apiPrefix}${env.openapiUrl}` 对应的文档路径。
保留 Storyworld 通用实现后去除领域耦合；users/user_identities/todos 是唯一初始 schema，重新生成初始 migration，SQL 生命周期由 schema 附属源码生成。todos.id 使用随机 UUID，ownerId 外键，createdAt/updatedAt 为毫秒时间；用户更新时间沿用数据库触发器，待办更新时间由数据库触发器维护。创建与更新后的返回值读取持久化结果。数据库异常只由统一边界转换，不吞错或重放写入。认证行为按所提取 manager 保留 state/nonce/PKCE、一次性事务、摘要 Session、TTL 和 OIDC 验签；日志不输出凭据。

## 权限与安全

认证只识别身份，授权独立检查实际 ownerId。创建归属来自 authorizeCreate，更新与删除先锁定真实记录再 authorize；不使用客户端 ownerId。回调验证 state/nonce/PKCE/issuer/audience，凭据日志脱敏，真实配置只放忽略的 .env.local。

## 状态一致性、事务与并发

PostgreSQL 为持久化权威；更新和删除在同一事务内 SELECT FOR UPDATE、授权并写入。mutateTodo 用 patch/null 重载明确返回待办或 null。身份映射采用数据库唯一键与事务幂等收敛；Redis 登录事务原子消费。PostgreSQL 身份与 Redis Session 不是跨存储原子事务，保持详细设计所述失败状态。

## 代码边界

Zod 在 HTTP 输入边界校验 title/completed/id；认证插件验证凭据，domain 验证实际资源归属。数据 DTO 不暴露 ownerId。schema 是结构事实来源；迁移由 drizzle-kit 和生命周期生成脚本生成，已经执行的 migration 不改写。

## 技术异常处理

认证管理器和统一响应插件分别保留 400/401/403/404/422/503 等结果。连接故障不自动重放写入。迁移与 OpenAPI 导出失败非零退出；没有明确恢复机制的错误自然上抛。所有判断与异常映射仅约束本服务端，不替客户端设计恢复页面。

## 环境配置落位

.env.example 在注释中列出当前服务器 PostgreSQL/Redis 地址和 PostgreSQL 用户名；DATABASE_URL、REDIS_URL、LOGTO_APP_ID、LOGTO_APP_SECRET 的默认值为空，MIGRATION_DATABASE_URL 仍为未启用的空示例。docs/env-rules.md 与 README 说明复制后必须填写新项目的独立库名、Redis 逻辑库编号及凭据。运行时 src/env.ts 的 required 校验不变；不新增未被运行时消费的环境变量，不自动创建或迁移现有服务器上的库。已有 .env.local 由用户管理，不随模板示例更新覆盖。

## 外部依赖

Bun、Elysia、Zod、PostgreSQL/Drizzle、Redis 和 Logto；各依赖在本仓库 manifest 显式声明。单元测试不访问外部服务；集成测试使用项目隔离数据库、Redis 和受控 OIDC HTTP 服务。

## 性能与资源限制

待办标题 trim 后 1..200 字符。列表是最小 CRUD 示例，仅按本人归属和时间索引读取，不引入检索平台。Session 和登录事务由 TTL 释放；数据库锁限于单次资源 mutation。

## 日志、监控与脱敏

命令记录执行阶段及失败退出，认证/请求日志脱敏；不输出 .env 内容、Token、Session 或组织凭据。验证记录区分受控联调、真实身份服务及浏览器结果。

## 迁移、兼容与回滚

旧个人服务端 HEAD 保留备份标签；新模板重新生成 users/user_identities/todos 初始 migration。模板不迁移实际 Storyworld 数据，不携带旧业务表和真实配置。回滚使用个人 Git 提交，数据库验证只在隔离环境执行。

测试预加载 tests/setup.ts 为缺失或空白的环境项注入隔离测试配置，保留非空的显式测试配置；仅作用于测试进程，不写入 .env.local，也不改变应用和 Drizzle 对空连接串的拒绝行为。

## 验证方案

bun run docs:check；bun run check；新隔离 PostgreSQL 与 Redis 上 db:migrate；认证集成测试使用受控 OIDC 服务；真实数据库待办创建、更新、删除与双用户越权用例；OpenAPI 快照与公开来源矩阵验证。文档入口由 `API_PREFIX + OPENAPI_URL` 组成，默认 `/api/openapi`，JSON 为该入口加 `/json`。验证启动日志路径与实际文档路由一致。app.ts 的 documentation.openapi 明确为 3.1.0；Zod 使用 JSON Schema 2020-12。Elysia 优先读取 Zod Standard JSON Schema 时同样与文档版本一致，nullable 字符串为 type:[string,null]，客户端必须生成 string|null。export-openapi.ts 从该 JSON 路由导出，不把文档 HTML 当作契约；成功写入后退出 CLI，避免运行时连接令生成命令悬挂。

## 联合开发实现

Server 环境解析提供可选 HOST。已配置时传给 HTTP 监听，缺省沿用框架默认值。

## 认证模式实现

`POST /auth/webhook/logto` 使用原始请求体校验 HMAC-SHA256 签名。有效通知按事件时间幂等更新 `logto_account_revocations`，提交后返回 `204`。旧通知不能覆盖已恢复或已删除的账号状态。Cookie 和 Bearer 在 Porthole 数据库中核对账号状态和凭证签发时间。Logto 未提供逐用户的角色分配事件，由同实例数据库中的关系变更记录经后台同步补齐。

登录协议在 auth/index.ts 按环境模式调用提供方。session.ts 统一发放、验证和清除 Cookie，按模式隔离 Redis 会话。local.ts 管理 PostgreSQL 自建账号、Argon2id 密码哈希及 Redis 登录限速。管理员用 auth:user 从标准输入传入密码。Logto 支持暂未配置时启动，认证路由报告配置错误。启动器使用公开命令 auth:config 读取同一解析器给出的模式和就绪标记，命令只输出公开配置。

## Porthole 业务模块

`src/porthole` 维护监听发现、分享与配额、访客入口和上游转发。管理 API 位于 `src/services/porthole.ts`。`src/index.ts` 先按 Host 分派管理和分享请求。实际 Socket 绑定 `PORTHOLE_BIND_HOST`，缺省为回环，回环的健康探针可直接访问。

`porthole_shares` 和 `porthole_sessions` 由 Drizzle schema 生成增量 migration。可选描述存为可空文本，编辑时省略字段会保留原值，显式清空保存为 null。`DELETE /porthole/shares/:id` 按当前账号和记录 ID 原子删除，访客会话由 PostgreSQL 外键级联清理。分享记录的 upstream_host_mode 默认是 original，local 模式从已绑定目标 URL 读取 host。旧客户端编辑时省略该字段，保留记录值。创建和重新连接从监听表重新解析目标，写操作和额度声明分别在事务内重新检查锁定行。曝光链接保留查询参数和路径，HTTP 不跟随上游重定向，只重写指向同一上游的地址。访客提交要求同源且限制表单体。有表单的访客页使用 same-origin 来源策略，使浏览器的原生表单提交保留 Origin；跳转到服务时使用 no-referrer。管理 API 使用已认证的 Logto 身份及来自 `/users/me` 的本地 ID，并按账号约束记录归属。沿用当前 Redis 会话命名空间，已有会话可继续使用。复用模板的 OpenAPI 导出入口和构建检查。

单元检查覆盖监听范围和转发边界。隔离集成验证使用独立数据库、Redis 和回环测试上游，覆盖权限、发布、并发额满、凭证与端口隔离、续期和撤销。
